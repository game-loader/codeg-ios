# 在 iOS 中使用多台服务器和工作树

本功能从 fork 的 `v1.0.1-sideload.17` 继续开发，保留现有普通聊天、文件附件、Bark 通知、学术、机器管理及数学渲染功能。

## 服务器与项目

在聊天标题菜单中管理服务器。每个服务器资料仍使用独立 UUID，令牌保存在既有 Keychain 存储中。

「文件夹」页默认按逻辑项目展示，同源仓库在各服务器和工作树上的历史会话汇总到一个项目下，每行保留原服务器与目录标记；「服务器」视图保留机器分组。身份来自服务端读取的 Git fetch remote，优先使用 upstream，其次 origin；不同路径、SSH/HTTPS 地址或 GitHub 大小写不影响同源关联。没有可识别来源的目录保持独立，同名路径和相同资源编号不会作为合并依据。

展开项目即可查看各服务器、仓库目录和工作树的会话，无需逐个展开机器目录。选择会话会在原服务器打开原会话；已完成、置顶会话保持可访问。新任务、打开文件夹与管理工作树通过明确的机器和目录选择运行位置，文件夹详情也保留会话、文件、Git 与终端入口。项目历史汇总不会改变会话归属或同步文件。

同源项目聚合需要包含 `list_repository_project_identities` 的新 Codeg Server。旧服务器保留独立目录并提示升级，升级后手动刷新可以重新识别。临时加载失败保留该连接已取得的身份，更换地址/令牌会清除旧代次的数据；修改 Git remote 后刷新可更新分组。

切换服务器后，原服务器的导航和会话草稿仍保留；会话顶部显示当前机器名称及地址。每台服务器的加载错误独立显示。iPad 可以在服务器菜单中选择「服务器分屏」，同时显示两个服务器；「单服务器」返回单视图。

各服务器的现有会话/项目导航按资料 UUID 和配置代次保存，不含令牌。重新启动后仅恢复匹配配置的资源引用；新聊天仍允许不绑定任何项目。

## 工作树管理

「管理工作树」查询对应仓库的完整 Git 清单，可看到主工作树、分离 HEAD、裸仓库、锁定与可清理标记，以及尚未加入 Codeg 工作区的检出目录。

新建时明确指定分支、服务器上的绝对路径及可选基础分支/提交。Git 创建成功而登记失败时使用「重试登记」，只重试加入工作区，不重新创建 Git 分支或工作树。打开已有检出目录也只进行登记。

移除确认页标明服务器、仓库、路径和分支。默认保留未提交内容及未合并分支的保护；删除分支及强制移除都需要明确选择。主工作树、当前工作树、裸仓库、锁定条目以及运行中任务的服务端保护继续生效。

如果检出目录已移除但分支清理失败，清单会刷新，并提供单独的分支清理确认。不会自动升级为强制删除。

完整清单和按路径移除需要包含多机器 worktree 功能的新 Codeg Server。旧服务器会显示升级提示，已有聊天、文件和原有 Git 功能继续使用。

## 配置变化与恢复

仅重命名或排序服务器不会替换它的工作区。更换地址、轮换令牌或删除资料会永久失效原代次，拒绝旧 HTTP 结果及后续步骤；操作不会转向另一台服务器。

该代次已打开会话的未发送草稿和队列文本会进入「恢复的草稿」，记录原服务器及地址。恢复记录只读，可选择文本或导出，不会自动发送或写入替换后的服务器。文件附件本身不包含在文本恢复记录中；已发送但尚未确认的消息应先核对原服务器会话。

应用进入系统后台时沿用 iOS 的连接与进程生命周期限制；保留工作区不意味着绕过系统后台限制。

## 验证

- 生产项目目录与合并历史核心测试：20 项通过，覆盖跨服务器编号冲突、置顶排序和失效路径。
- 保留工作区、历史路由与部分加载失败的架构探针：32 项通过；固定 HTTP 路由和资料代次检查另有 11 个断言通过。
- 全项目 Swift 语法解析通过；新增原生测试覆盖实际会话选择、新任务目标、草稿和 Git/终端状态保留。
- Linux 便携测试与语法检查不等同于 SwiftUI 原生编译。原生设备构建、模拟器 XCTest 和 IPA 打包结果以 [fork Actions](https://github.com/game-loader/codeg-ios/actions) 对应源码提交的日志为准；手动 iPad 交互单独验收。
